# 2026.09.30-rc.1 — functional reliability candidate

Base: 6e890cb4323730249efe0f4705c718e095f97219. Branch: fix/read-reliability-20260929.
User requested fixes from the independent functional audit before the morning field test. This is a field-test candidate, not a new hardware compatibility certification.

## Implemented

- F01/F05: bounded connect, service/characteristic discovery and notifications; bounded LIVE writes; cancellation starts at connection/read preparation; per-device ownership prevents late completions from disconnecting a successor; screen teardown cancels pending opens; stale LIVE refresh results are ignored.
- F02: LIVE refresh yields between individual UDS requests when a card handoff is requested. The active request drains before the final stationary check. No parallel LIVE/download session is introduced.
- F04: break analysis runs against canonical UTC history; only finding labels are localized. CSV includes UTC instants and local UTC offsets to distinguish repeated DST hours.
- F06: a verified read remains available in memory/export if local persistence fails. UI explicitly says not saved and never claims saved success; the earlier durable snapshot remains untouched.
- F08: each simple download command has a 90-second absolute deadline in addition to the existing response timeout. Repeated NRC 0x78 cannot extend it indefinitely.
- F09 (limited): a failed network refresh preserves only an already verified active deadline in the current open tab, without extending the 72-hour trial. Reload still requires online verification. The UI explains offline access. Session checks no longer require email-sending configuration.
- F10: UI and CSV explicitly label the existing conservative data cutoff as the start of the read; it is not relabeled as transfer completion.
- Card result display no longer waits for final telemetry delivery.
- Visible release identifier and service-worker cache changed together.

Unchanged: golden protocol command bytes, ACK scheme, parser acceptance rules, five-second LIVE/download release pause, 90-second first packet timeout, 60-second packet idle timeout, 72-hour server trial, main-domain DNS and mail provider bindings. No database migration.

## Open findings (not claimed fixed)

- F03: no continuous application speed measurement during the separate download session. Existing stationary preflight stays. Movement behavior needs a safely organized physical test, not new speculative Bluetooth commands.
- F07: nonconsecutive dates remain rejected until real supported card samples/specification confirm which gaps are legitimate. No invented rest/zero days.
- F11: local snapshots still belong to the browser profile, not separate accounts. Account isolation/migration is a separate change; users of a shared phone must explicitly clear local data. Existing saved-card selection and delete controls remain.
- F12: discovery stays broad until actual advertisement/service behavior is confirmed for the supported models; no name filter that could hide a working device is introduced.
- Multi-tab PWA update behavior, background suspension and physical radio coexistence still require field verification.
- Admin/telemetry completeness findings from the earlier audit are separate and remain open.
